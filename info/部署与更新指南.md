## 二、日常更新（改内容 / 加作品 / 改联系方式）

### 方式 A：找 AI 助手帮你改（推荐）

把新作品素材（图片/视频）或要改的内容发给 AI 助手，让它完成：

1. 更新 `index.html`（增删板块、改文字）
2. 把新素材放进 `img/` 或 `video/`
3. 推送到 GitHub

推送后两个网站都会**自动部署**，无需其他操作。

```bash
git clone https://github.com/wu-nai-a/portfolio.git
# 修改 index.html；加图片放 img/，加视频放 video/
git add -A

git push origin main
```

> ✅ 推送即完成。GitHub Pages 约 1 分钟生效，Cloudflare Pages 约 1~2 分钟生效。

## 三、Cloudflare 自动部署：原理与首次配置

### 为什么用 GitHub Actions，而不是后台的「连接 Git 仓库」

Cloudflare 后台那个「Connect to Git / 连接到 Git」功能，要求项目是 **Git 集成**类型。而你这个项目是早期用 `npx wrangler pages deploy` 手动上传创建的 **Direct Upload（直接上传）** 项目。Cloudflare [官方明确说明](https://developers.cloudflare.com/pages/get-started/direct-upload/)：

> 如果您选择直接上传，之后将无法切换到 Git 集成。您必须创建一个新的 Git 集成项目才能使用自动部署。

也就是说，想用后台的 Git 集成，**只能删掉现在这个项目、重建一个新的**。但删项目意味着：

- `zouxunhao-portfolio.pages.dev` 会短暂中断
- 这个子域名是全局唯一的，删掉后**有被他人抢注的风险**（官方没有承诺保留期）
- 而这个名字已经印在简历上，风险不值得冒

**所以改用 GitHub Actions**：在仓库里放一个 workflow 文件，每次推送到 `main`，由 GitHub 的服务器调用 Cloudflare 接口把新版本传上去。

- ✅ 项目不用删，**网址完全不变**
- ✅ 历史部署记录、自定义域名、任何现有配置都不受影响
- ✅ 效果一样：推送即自动上线，不用再手敲命令

自动部署脚本在 `.github/workflows/pages-deploy.yml`。

### 首次配置（只需做一次）

> 下面每条都给了 **中文界面 / 英文界面** 两种说法，按你界面上看到的对照即可。

#### 第 1 步：创建 Cloudflare API 令牌

1. 打开 <https://dash.cloudflare.com/profile/api-tokens>
   （中文路径：右上角头像 →「**我的个人资料 / My Profile**」→「**API 令牌 / API Tokens**」）
2. 点「**创建令牌 / Create Token**」
3. 在「**自定义令牌 / Custom Token**」一栏下点「**开始使用 / Get started**」
4. 「**令牌名称 / Token name**」填 `portfolio-pages-deploy`
5. 「**权限 / Permissions**」依次选三格：
   - 第一格：`账户 / Account`
   - 第二格：`Cloudflare Pages`
   - 第三格：`编辑 / Edit`
6. 点「**继续到摘要 / Continue to summary**」→「**创建令牌 / Create Token**」
7. **立刻复制这串令牌** —— 官方原话：Token secret **仅显示一次**，关掉页面就再也看不到了

#### 第 2 步：拿到 Cloudflare 账户 ID（Account ID）

- 方法一：登录 Cloudflare 后看地址栏，形如 `dash.cloudflare.com/<中间这一串就是账户 ID>/...`
- 方法二：后台「**概览 / Overview**」页面，右侧菜单的「**API**」区域里能看到「**账户 ID / Account ID**」
- 官方中文说明：<https://developers.cloudflare.com/fundamentals/account/find-account-and-zone-ids/>

#### 第 3 步：在 GitHub 仓库添加两个 Secret

GitHub 界面目前中文翻译不完整，多数按钮仍是英文，对照着找：

1. 打开 <https://github.com/wu-nai-a/portfolio/settings/secrets/actions>
   （路径：「**Settings / 设置**」→ 左侧「**Secrets and variables / 密钥和变量**」→「**Actions**」）
2. 点「**New repository secret / 新建仓库密钥**」，添加两条：

| Name（名称）填写 | Secret（密钥值）填 |
|---|---|
| `CLOUDFLARE_API_TOKEN` | 第 1 步复制的那串令牌 |
| `CLOUDFLARE_ACCOUNT_ID` | 第 2 步拿到的账户 ID |

> 名称必须**一模一样**（全大写、下划线），写成别的会自动部署脚本会报 `Input required and not supplied: apiToken`。
> Secret 加密存储，添加后无法再查看内容，只能重新设置；运行时才解密注入，不会出现在日志里。

#### 第 4 步：推送，触发第一次自动部署

```bash
git push origin main
```

#### 第 5 步：验证

1. 打开 <https://github.com/wu-nai-a/portfolio/actions>，应看到 **Deploy to Cloudflare Pages** 正在运行
2. 等它变成绿色 ✅（约 1 分钟）
3. 打开 <https://zouxunhao-portfolio.pages.dev/>，确认页面正常

> 之后每次 `git push origin main`，这个工作流都会自动跑一遍。

### 排查

| 现象 | 原因与处理 |
|---|---|
| Actions 报 `Input required and not supplied: apiToken` | 两个 Secret 名称写错了或没添加，回第 3 步重做 |
| Actions 报 `Authentication error` / 错误码 `10000` | 令牌权限不对，需要 `账户 / Account → Cloudflare Pages → 编辑 / Edit`；或令牌已被删除，重新生成并更新 Secret |
| Actions 成功，但网址内容没变 | 部署被当成「预览部署」了。看工作流日志输出的部署地址：如果是 `<一串字符>.zouxunhao-portfolio.pages.dev` 而非正式地址，说明项目「生产分支」不是 `main`（工作流里已有自动修正步骤，再推一次即可） |
| Actions 页面找不到工作流 | workflow 文件还没推上去，确认 `.github/workflows/pages-deploy.yml` 已在仓库里 |
| 部署报某个文件超过 25 MiB | Cloudflare Pages 单文件上限 25 MiB，压缩该文件（见第六节） |

### 令牌安全

- 令牌只存在 GitHub Secrets 里，权限仅限 `Cloudflare Pages: Edit`，拿不到你账号的其他东西
- 令牌如果泄露或想作废：Cloudflare 后台删掉旧令牌 → 生成新令牌 → 在 GitHub 里更新 `CLOUDFLARE_API_TOKEN` 这个 Secret 即可
- 早期用于手动上传的旧令牌已经不需要了，建议删除：<https://dash.cloudflare.com/profile/api-tokens>

## 四、网站是全中文的，需要注意什么？

**结论：中文网站对这套部署流程没有任何影响。** 因为本站没有构建步骤，Cloudflare 就是把文件原样托管，不存在编译/转码环节。

已核对的实际状态：

| 检查项 | 状态 |
|---|---|
| `<html lang="zh-CN">` | ✅ 已设置，浏览器/搜索引擎可正确识别语言 |
| `<meta charset="UTF-8">` | ✅ 已设置，中文不会显示成乱码 |
| `index.html` 文件编码 | ✅ 合法 UTF-8 |
| `pages-deploy.yml` 文件编码 | ✅ 合法 UTF-8，工作流里的中文注释在 Actions 的 Linux 环境正常显示 |
| 素材文件名 | ✅ 图片/视频全部是英文名（`img_00.jpg`、`v_fox.mp4`），最稳妥 |

几个可能踩到的点：

- **中文文件名可以保留**：`info/` 下 3 个中文名 `.md` 会被部署成百分号编码的网址（如 `/%E9%83%A8%E7%BD%B2...`），能正常访问，只是不好看。新增素材时**仍建议用英文/拼音名**，链接更干净、跨平台更稳
- **中文写在 commit message 里**：没问题，仓库一直是这么提交的
- **不要用 GBK/ANSI 保存 `index.html`**：必须保持 UTF-8，否则中文全乱。用 VS Code 打开时右下角能看到编码，应为 `UTF-8`
- **页面里已有的手机号/邮箱是刻意公开的**：中文内容不影响这点，但别再加其他隐私信息

## 五、以后想彻底摆脱网址焦虑（可选，长期建议）

`*.pages.dev` 这个子域名是 Cloudflare 的，你只是借用；而简历上一旦写死，每次换平台都要改简历。

更省心的长期做法：**注册一个自己的域名**（如 `zouxunhao.com`，一年几十块），然后在 Cloudflare 后台把这个域名加为「**自定义域 / Custom domain**」指向当前 Pages 项目。

- 域名归你所有，指向哪个平台随时可以改，**网址永远不用再变**
- 以后要换到 Vercel、自己服务器、或改用真正的 Git 集成，链接都不用动
- 建议做法：等下次更新简历时，把新域名和这个 `pages.dev` 地址**一起写上**，过渡一段时间，之后再只用新域名

## 六、素材要求

| 素材 | 建议规格 |
|---|---|
| 图片 | JPEG/PNG，单张 ≤ 500KB，宽度 ≥ 1200px 清晰度最佳 |
| 视频 | MP4 H.264，720p（1280px 宽），单个 ≤ 20MB，网页播放流畅 |
| 格式 | 中文文件名建议改成英文/拼音（如 v_fox.mp4），避免特殊字符 |

> ⚠️ **Cloudflare Pages 硬限制**：单个文件必须小于 **25 MiB**，文件总数不超过 20000 个。
> 目前仓库最大文件是 `video/v_jianmo.mp4`（9.5MB），远低于上限，无需处理。
>
> 视频压缩参考命令：
> ```bash
> ffmpeg -i 输入.mp4 -vf "scale='min(1280,iw)':-2" -c:v libx264 -preset veryfast -crf 28 -c:a aac -b:a 96k -movflags +faststart 输出.mp4
> ```
